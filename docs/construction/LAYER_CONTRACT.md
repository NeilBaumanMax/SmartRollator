# 分层契约

## 依赖规则

| 层 | 可依赖 | 禁止依赖 |
|---|---|---|
| L5 可观测性 | L0–L4 的只读公开状态 | 直接写执行器、改变控制参数而无命令通道 |
| L4 安全仲裁 | L0–L3 接口 | 绕过驱动接口、隐藏故障 |
| L3 控制域 | 公共数据类型、数学工具 | HAL、RTOS、UART/CAN、printf、全局任务句柄 |
| L2 实时服务 | L0、L1、公共数据类型 | 协议私有字节布局、控制数学细节 |
| L1 设备协议 | L0 适配接口 | 控制策略、UI/实验逻辑 |
| L0 平台 | 厂商 HAL、RTOS | 上层产品业务对象 |

## 接口约定

- 公共接口必须注明输入/输出单位、范围、线程上下文、所有权、超时和错误语义。
- 协议解码结果先转成领域结构体，再交给任务或控制层。
- 控制函数优先采用 `init/reset/step` 形态，状态由调用者持有，便于多实例与测试。
- 平台接口返回显式状态，不以日志作为错误传播机制。
- 执行器接口接收经过仲裁的 `WheelCommand`，并回报最近应用的序号与状态。

## 代码位置建议

```text
Core/                  CubeMX 生成入口与 USER CODE 钩子
Drivers/               STM32/HAL 第三方驱动
Middlewares/           FreeRTOS 与第三方中间件
App/platform/          L0 适配
App/devices/           L1 设备与协议
App/services/          L2 实时服务
App/control/           L3 纯 C 控制域
App/safety/            L4 安全仲裁
App/observability/     L5 日志与指标
Tests/host/            主机侧单元/回放测试
Tests/bench/           台架步骤、脚本与证据索引
```

最终目录可在 Phase 1 冻结，但必须保持上述责任分离。

## 变更门槛

新增跨层调用前必须回答：为什么现有接口不能满足、错误如何传播、如何主机测试、实时预算如何保证、失效时如何进入安全状态。若改变依赖方向，先更新架构决策记录再编码。
