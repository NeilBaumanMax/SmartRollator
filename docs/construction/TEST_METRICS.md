# 测试与指标

## 证据等级

| 等级 | 说明 | 可证明内容 |
|---|---|---|
| T0 静态 | 代码审阅、格式、链接、静态分析；实际编译时另记诊断 | 已检查范围内未发现问题；人工审阅不证明编译或运行正确 |
| T1 主机 | 单元、属性、记录回放、数值测试 | 纯逻辑与算法行为 |
| T2 目标板 | 烧录、启动、外设回环、时序测量 | MCU/RTOS/外设集成 |
| T3 台架 | 传感器、电机抬轮、CAN 分析、故障注入 | 真实设备交互与安全路径 |
| T4 系统 | 长稳、完整场景、等价验收 | 系统级非载人能力 |

T0/T1 不能替代 T2/T3。V1 不包含人体测试。

## 普通 STM32 增量的默认验收

按用户 2026-10-17 指令，普通代码施工可以静态代码自检作为本次增量的验收依据；不为每次小改动强制烧录或搭建新测试框架。已有且适用的近邻检查仍执行。以下项目按改动范围选择，未涉及项注明不适用：

- 工程完整性：.ioc、Keil 文件/包含路径、声明与定义、调用方、生成区/USER CODE 边界。
- C 代码：初始化、指针/数组边界、资源生命周期、整数宽度与溢出、错误返回处理。
- 协议/算法：长度与校验、字节序、单位和符号、超时及时间戳回绕、NaN/Inf、饱和及参数边界。
- RTOS/ISR：共享状态同步、阻塞调用、队列满/失效路径、ISR 调用约束。
- 控制安全：上电失能、失联/故障降级、限速限幅、唯一命令仲裁出口。

LOG 至少记录具体文件或函数、输入/边界/故障路径、发现及修复、自检结论与尚不能证明的事项，不能仅写“已自检”。纯文档任务检查链接、状态一致性与工程保全即可。

静态审阅通过可使本次普通代码增量完成；编译、主机执行、烧录、实机验证分别记录未运行/未建立。P1.03 生成、P1.05 实际编译及台架/系统验收节点仍需要相应真实证据，不能因代码增量已提交而把整个阶段标成完成。下列模块测试集是相应功能/阶段验收要求，不强制每个普通增量重复完整矩阵。

## 通用记录格式

每次测试记录：日期、提交哈希、硬件版本、工具版本、命令/步骤、预期、实际、原始证据路径、结果、执行人。首次失败与修复后复测必须是两条独立记录。

## 当前指标状态

以下阈值在没有硬件规格和基线测量前均为 `未建立`，不得擅自填入猜测值：

- 控制周期、抖动和最坏执行时间。
- 传感器有效采样率、端到端延迟、超时阈值。
- CAN 总线速率、PDO 周期、命令确认和失联阈值。
- 最大线速度、角速度、加速度和减速度。
- 任务栈余量、CPU 占用和日志带宽。
- Hopf 振幅/频率误差、收敛时间和允许步长。

## 各模块最低测试集

- 协议：金样帧、最短帧、坏校验、未知命令、分包、粘包、超时、计数溢出。
- 数据模型：单位/符号、边界、时间戳回绕、无效标志和旧数据拒绝。
- 固定导纳：零输入、恒定力、阶跃、正负方向、饱和、复位、NaN/Inf。
- Hopf CPG：复位、极限环收敛、幅频准确性、参数边界、步长敏感性、长时间有限值。
- 安全仲裁：上电失能、输入失联、CAN 故障、急停、任务失活、模式切换和恢复条件。
- RTOS：周期、抖动、队列满、日志拥塞、栈余量和看门狗。
- 电机台架：节点状态、左右方向、速度单位、低速阶跃、斜率限制、断线与重新上电。

## 阶段完成判定

只有该阶段列出的全部适用测试有证据且无未解释关键失败时才可标记 Passed。因缺少工具或硬件未执行的测试写 `Not run`，并使相应阶段保持 `Partially complete`。
