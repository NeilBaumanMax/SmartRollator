# 决策记录

## ADR-001 — 从独立仓库重建

- 日期：2026-08-07
- 状态：Superseded in local-path scope by ADR-007；保留其“参考状态不得冒充验证证据”原则
- 历史决策：最初拟将旧工程作为只读参考，并在旁路目录按阶段恢复能力；本地路径安排已由 ADR-007 废止。
- 原因：获得干净历史、明确回滚点和可复现施工过程。
- 影响：旧工程中的“可用”结论不能自动继承为新工程的验证证据。

## ADR-002 — Docs-first 施工

- 日期：2026-08-07
- 状态：Accepted
- 决策：编码前建立产品、架构、计划、测试、Git、日志和交接文档。
- 原因：让每个阶段范围、验收和真实状态可追溯，并支持 AI Agent 接力。

## ADR-003 — 单向分层与纯 C 控制域

- 日期：2026-08-07
- 状态：Accepted
- 决策：采用 L0–L5 单向分层，固定导纳与 Hopf CPG 不依赖 HAL/RTOS。
- 原因：提高可测试性、可移植性和故障定位能力。

## ADR-004 — 唯一安全命令出口

- 日期：2026-08-07
- 状态：Accepted
- 决策：所有电机命令经过安全仲裁；控制算法与任务不能直接写驱动器。
- 原因：集中实现使能、限幅、斜率、超时和故障降级。

## ADR-005 — 先固定导纳、后 CPG

- 日期：2026-08-07
- 状态：Accepted
- 决策：先验证固定导纳基线，再独立验证 Hopf CPG，最后可切换集成。
- 原因：保留可比较基线，避免算法与平台问题相互掩盖。

## ADR-006 — 单远端双轨历史

- 日期：2026-08-07
- 状态：Accepted（依据产品负责人提供的项目远端）
- 决策：同一 GitHub 仓库使用独立根历史保存 `main` 重建主线与 `reference/archive-*` 旧工程归档；二者不合并。
- 原因：既满足旧资产全量取证与远端备份，又保持重建主线没有旧生成物和未经验证状态。
- 影响：默认分支必须是 `main`；归档分支只读，不能作为构建或硬件通过证据。

## ADR-007 — 当前工程目录作为正式本地仓库

- 日期：2026-08-07
- 状态：Accepted；覆盖 ADR-001 中“必须在独立目录施工”的本地路径部分。
- 决策：根据产品负责人明确纠正，直接在其当前工作区的工程根目录初始化 Git，并把完整工程纳入远端 `main`。
- 原因：正式工作入口必须与产品负责人当前打开和维护的工程目录一致，避免旁路仓库不可见或交付认知不一致。
- 影响：`reference/archive-20260807` 继续保存纳入 Git 前的证据；`main` 从完整工程基线起按阶段重建，旧代码存在仍不等于已编译或已验证。

## ADR-008 — 工程与参考资产分离及可发现性

- 日期：2026-10-16
- 状态：Accepted，依据用户整理工作区、补入参考资产与文档去重指令。
- 决策：STM32 完整工程保持根目录结构；Files 统一保存参考资料，docs 保存正式施工事实源。AGENTS → INDEX → WORKSPACE_MAP/ASSET_INDEX 提供全范围入口；明确本地未跟踪资料和未来 App/Tests 的边界。
- 去重：同主题文档按内容与版本证据保留较新版本，3 份旧 DOCX 从工作树移除，远端备份和 DUPLICATES 记录保留恢复依据；不触碰厂商文件或改写历史清单。

## ADR-009 — 全工作区普通文件备份

- 日期：2026-10-16
- 状态：Accepted，依据用户“工作区里的文件全部备份到 GitHub，不要有剩余”的最新明确指令。
- 决策：覆盖此前排除构建输出/IDE 状态/预览/系统元数据以及研究笔记仅本地保留的规则；现有文件按字节备份，保留原相对路径，.git 内部数据库不重复纳入。
- 证据：全文件清单、SHA-256、精确暂存及独立远端快照验证；新增敏感文件不得静默上传或遗漏。
- 影响：备份体积增大，旧状态中机器路径和旧日志不作为可移植配置或固件验证。上层同内容文件归并到已跟踪副本，源路径映射保留。
