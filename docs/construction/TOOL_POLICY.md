# 工具政策

## STM32CubeMX

- `.ioc` 是 MCU 引脚、时钟、外设和 RTOS 生成配置的事实源。
- 记录 CubeMX 与固件包版本；重新生成前工作树必须可回滚。
- 业务实现只放 USER CODE 区或独立 `App/` 模块。
- 生成成功只证明生成器完成，不证明工程可编译。

## Keil MDK

- 记录 MDK、Arm Compiler、Pack 版本与目标配置。
- 构建必须保存错误/警告摘要；警告不静默忽略。
- `.uvprojx/.uvoptx` 中机器路径和个人选项需要审查，避免不可移植状态。
- 只有实际构建日志可写“编译通过”。

## 主机侧测试

- 控制域和协议纯逻辑优先使用标准 C 编译器运行测试。
- 测试脚本必须有固定入口、非零失败码和可复现依赖说明。
- 格式化工具只做机械改动，运行后审阅 diff。

## 串口、CAN 与台架工具

- 记录端口、波特率/位速率、节点 ID、接线版本和采集时间。
- 原始日志作为证据，不直接提交含隐私或体积过大的数据；仓库中保存摘要和索引。
- 发电机命令、台架脚本默认从最低安全输出开始，电机测试必须抬轮或机械隔离。

## Agent 与 Shell

- 文件查找优先 `rg`/`rg --files`。
- 文本修改使用可审阅补丁，避免覆盖不明改动。
- 不把工具输出截断后的片段当作完整成功证据。
- 自动化脚本不能隐藏底层命令、错误码或生成物位置。
