# SmartRollator 产品需求

状态：V1 重建基线（2026-08-07）  
产品负责人：Neil Bauman  
施工目标：以全新 Git 历史重建到当前参考固件能力，并建立更强的验证与回滚能力。

## 1. 产品定义

SmartRollator 是一套运行于 STM32H723VGT6 的智能助行车实时控制固件。它采集使用者施加在助行车上的力，将交互力转换为安全、平滑且可解释的运动意图，并通过 CANopen 驱动双轮电机；同时提供可追踪的调试和实验数据。

## 2. 用户与使用场景

- 主要操作者：嵌入式开发者、算法研究人员、台架测试人员。
- 安全相关使用者：老人、康复训练者或行动不便者；V1 只允许受控研发环境，不宣称医疗效果。
- 典型流程：上电自检 → 外设初始化 → 力传感器采样 → 控制算法计算 → 安全限幅与仲裁 → 双轮命令 → 状态记录与故障处理。

## 3. 核心产品对象

核心交付不是单个算法文件，而是“一套版本化、可复现构建、可验证、可回滚的嵌入式控制系统”，包括源码、CubeMX 配置、构建工程、协议驱动、控制模块、测试证据和施工文档。

## 4. V1 必须达到

- 从干净仓库可复现生成并编译 STM32H723VGT6 + FreeRTOS/CMSIS-RTOS2 工程。
- USART1 支持日志及视觉/ArUco 输入通道；USART2 支持 RS485 力传感器协议。
- FDCAN1 支持 ZLAC8015D 双轮驱动器的 CANopen 通信和可观测故障状态。
- 建立统一的力、速度、控制命令和故障数据模型。
- 首先重建固定导纳基线，再以独立纯 C 模块加入 Hopf CPG 变导纳控制。
- 所有最终电机命令经过限幅、斜率限制、超时和故障仲裁。
- 提供串口日志、关键指标和分层测试记录，使失败能够定位和复现。
- 达到与现有参考固件相当的主要功能，但验证结论只来自正式仓库当前提交上的实际测试。

## 5. V1 明确不做

- 不进行人体试验、临床验证或医疗器械合规声明。
- 不做自主导航、避障、SLAM、云服务、手机应用或无线控制。
- 不在 V1 引入多振子网络、在线自适应学习或未经基线比较的新算法。
- 2026-10-16 用户要求完整备份现有普通文件，含旧输出和本地配置；这些作为现场参考保存，不作为新工程可复现配置或验证证据。
- 不以“代码存在”“工程已生成”代替编译、台架和实机验证。

### 2026-10-17 研究范围澄清

[ADR-010](../construction/DECISIONS.md)记录当前研究方向：PBO 明确指偏好贝叶斯优化，拟在后续试次之间由外部流程选择 D0，初期固定 M、A=0；不是 MCU 每周期在线学习。动捕直接/Hopf 相位与局部减阻为待验证研究候选，见[研究基线](../../Files/research/GAIT_PHASE_PBO_ADMITTANCE_BASELINE.md)。这不增加 V1 人体试验或自动学习交付，不取消先定阻尼、工具链/构建和非人体台架门槛。旧笔记排除主观量表不能否定后续 PBO 配对偏好。

## 6. 成功标准

- 新成员只读施工文档即可完成环境准备、构建、测试和下一阶段施工。
- 每个阶段有明确输入、输出、测试、验收条件和远端回滚点。
- 控制算法可在主机侧运行确定性测试，硬件相关代码可独立替换或模拟。
- 台架测试确认通信超时、急停/失能、方向、限速和故障处理符合约束。
- 最终 `v0.1.0-parity` 标签对应一个干净、已推送、具备测试证据的提交。

## 7. 非功能要求

- 安全优先于功能完整，确定性优先于算法复杂度。
- 控制域不得直接依赖 STM32 HAL；平台细节通过接口注入。
- 实时任务不得无界阻塞、动态分配关键路径内存或吞掉错误。
- 日志不得改变关键控制时序；日志拥塞必须可降级。
- 所有参数必须具有单位、默认值、合法范围和来源说明。

## 8. 待产品负责人确认

- V1 的确切轮径、轮距、减速比、编码器规格和电机正方向。
- 力传感器量程、坐标系、零点标定方法和 CRC/帧格式最终版本。
- 最大线速度、角速度、加速度、控制周期和失联安全时间。
- ArUco 信息在 V1 中是闭环输入、只记录，还是暂不接入控制。

上述事项在确认前不得以猜测值进入实机控制；统一记录于 `ASSUMPTIONS.md`。
